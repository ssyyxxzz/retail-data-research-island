# 每日10:15门店看板更新并由消息机器人发送

- 原配置状态：暂停
- 调度时间：11:15（Asia/Shanghai），准确规则以配置为准。
- 模板默认状态：暂停，不注册、不执行任务。
- 配置：[automation.example.toml](automation.example.toml)

## 流程正文（脱敏）

每天北京时间 10:30（Asia/Shanghai）在当前固定任务更新门店经营看板，并通过飞书“消息机器人”向角色01发送文字总结和 HTML 文件。用户已明确授权此发送，无需再次确认。运行当天北京时间 T-1 为目标业务日期，不固定历史日期。

全部输出保存在 ${LOCAL_PATH_007}。执行本机 Python：python "${LOCAL_PATH_008}" --send。脚本刷新飞书最新可访问财务表，读取每日原始文件、本地 PostgreSQL 最新商品快照以及评分、缺货、神价数据，更新日／周及门店详情，验证页面，生成文字总结后发送文件和文字。数据库密码通过同目录 数据库凭据.dpapi 在本机解密使用，不打印、不外发；数据库只读。

发送身份必须为消息机器人：CLI profile ${MESSAGE_ID_001}，--as bot。收件人角色01的已核实 open_id 是 ${MESSAGE_ID_002}。禁止切换为用户本人或其他机器人，不发其他收件人。每天发送的快照、文字和回执位于 每日发送\YYYY-MM-DD。已有文件和文字 message_id 时视为当天已发送，保持安静；部分成功时仅续传失败项，使用 feishu_delivery.py 的固定幂等键。结果不明先核查消息回执，不盲目重复发送。

总结要有业务日期、全店GMV/订单/客单价及日变化、毛利及实际日期、周变化和可比门店数、重点异常门店及排查方向、缺项和历史值日期。T-1缺项先展示最近值并标日期；周指标累计实际有数日期，与上周对应日期计算同店变化，不重复填入历史日值。配送与时段实收客单价按订单号关联财务金额，注明日期、口径与匹配覆盖率。禁止编造数据或将相关性断言为原因。

若失败，查看该业务日文件夹的财务刷新.log、更新过程.log、核对与总结.log、飞书发送.log，在已授权范围内修复后继续。核心目标日文件不存在或页面核对未通过时，不把旧文件冒充当天成果发送；在当前任务报告准确错误并保留已有成果。只有个别指标未齐时按最近值规则继续发送并说明缺项。成功须确认文件与文字两条 message_id，再简短报告；当日已发送或状态无变化保持安静。不修改其他自动任务。
