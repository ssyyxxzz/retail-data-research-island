# 六店门店日报及老店改造看板每日更新

- 原配置状态：暂停
- 调度时间：14:00（Asia/Shanghai），准确规则以配置为准。
- 模板默认状态：暂停，不注册、不执行任务。
- 配置：[automation.example.toml](automation.example.toml)

## 流程正文（脱敏）

每天14:00（Asia/Singapore）在 ${LOCAL_PATH_003} 启动六家门店日报流程。执行前先检查仍会显示“未开始”的人工填写项目，在当前任务中向用户发送简洁清单并等待回复；用户明确仍未开始或未提供具体数值的继续写“未开始”，不得猜测。用户未回复时不生成最终日报。

从${REFERENCE_DATE_009}起只处理以下六家门店：${BUSINESS_IDENTIFIER_007} 示例零售门店（示例门店〈05〉）、${BUSINESS_IDENTIFIER_008} 示例零售门店（示例门店〈18〉）、${BUSINESS_IDENTIFIER_001} 示例零售门店（示例门店〈20〉）、${BUSINESS_IDENTIFIER_009} 示例零售门店（示例门店〈31〉）、${BUSINESS_IDENTIFIER_010} 示例零售门店（示例门店〈58〉）、${BUSINESS_IDENTIFIER_011} 示例零售门店（示例门店〈63〉）。从${REFERENCE_DATE_009}起不再处理示例门店〈11〉店；同时不处理示例门店〈48〉、示例门店〈13〉、示例门店〈56〉、示例门店〈53〉。不得在9月3日及以后新生成的工作簿、截图、询问清单、当天JSON和成功报告中包含这些门店。示例门店〈11〉店截至${REFERENCE_DATE_010}的历史数据保留，不删除、不追溯修改；看板历史日期可保留示例门店〈11〉店记录，但9月3日及以后的当日门店列表、趋势和周度数据不得新增示例门店〈11〉店。

竞对盘查优先使用已登录Chrome只读打开飞书多维表：${SERVICE_URL_002} 。只按上述六店名称匹配“竞对类目（已完成）”；空白、无法匹配或访问失败时不得猜测，显示“未开始”并询问。禁止修改飞书表。

固定总部要求补货商品数：${REPLENISHMENT_TARGETS}。已补货数是持续累计字段，每天必须先继承最近一次确认的累计值，不得因当日无新增或用户说“其他未开始”而回退为“未开始”。截至${REFERENCE_DATE_011}的累计基准为：${CONFIRMED_CUMULATIVE_BASELINE}。用户明确“新增X个”时才在累计值上加X，并标注“进行中（今日新增X个）”；用户未明确新增时，提供值按累计值处理；无新增沿用累计值，状态“进行中”。到货数、在途数取当天最新补货/采购结果，取不到则询问。

自动取得：KVI重点商品有货率、类目热销商品有货率、今日售罄商品数、顾客消息回复率、商品负反馈新增数、全渠道订单数、全渠道单均毛利、美团订单数、美团单均毛利、饿了么订单数、饿了么单均毛利、商品成本率。美团单均毛利按源数据固定加1.3元；调整后的全渠道单均毛利按（原全部线上毛利合计＋美团订单数×1.3）÷全部订单数计算；饿了么不调整。亏损订单改善按最近两期门店亏损订单占比比较。

每天在 ${LOCAL_PATH_016} 根目录按文件修改时间选择最新的、文件名以“门店店铺等级明细”开头的xlsx文件（忽略~$临时文件）；即使当天没有新文件，也使用目录中最新一份成功文件并记录源文件日期。按完整门店名称匹配六店，读取“客户端展示评分”作为“店铺评分”，并读取“缺货退款率”“3分钟IM人工回复率”“配送准时率”“商品负反馈率”。四个率优先把百分比文本转为数值；指标值为等级文本时，使用“指标分子值÷指标分母值”计算真实百分比。缺失、分母为0或门店无法匹配时用null，不得猜测。JSON字段为 shop_score、shortage_refund_rate、im_3min_reply_rate、delivery_ontime_rate、product_negative_feedback_rate、store_level_source_date。日报保留独立“平台店铺表现”区域；无数据写“未开始”。看板在单店详情、每日趋势和周度变化中展示这五项。店铺评分、3分钟IM回复率、配送准时率越高越好；缺货退款率、商品负反馈率越低越好。未提供合格阈值前，只展示数值和变化，不纳入日报不合格清单和整体达标率。

合格规则：KVI<90%不合格；热销有货率<90%不合格；售罄数<300合格、>=300不合格；顾客消息回复率<90%不合格；商品负反馈新增数>3个不合格。不合格情况集中在日报底部。

生成一个Excel工作簿，只含六个日报Sheet，顺序：示例门店〈05〉、示例门店〈18〉、示例门店〈20〉、示例门店〈31〉、示例门店〈58〉、示例门店〈63〉；不生成商品明细。保存到 ${LOCAL_PATH_023}。当天JSON保存到 ${LOCAL_PATH_024}。数值保持数值类型，缺失自动指标用null，人工未开始写“未开始”。

在 ${LOCAL_PATH_025} 保存六张日报PNG，不生成商品明细截图。保持白底、浅米黄色表头、黑色细边框风格，日报不显示取数规则、说明、备注、数据状态。

完成日报及截图后更新公网“老店改造看板”。项目固定 ${LOCAL_PATH_026}，Cloudflare Pages项目 laodian-gaizao-dashboard，地址 ${SERVICE_URL_003}，不新建站点。运行 node scripts\prepare-history.mjs、npm.cmd run build、npm.cmd run export:static、npx.cmd wrangler pages deploy static-dist --project-name laodian-gaizao-dashboard --branch main --commit-dirty=true。history优先兼容 six_store_dashboard_data.json，并兼容历史 seven_store_dashboard_data.json、ten_store_data.json；历史日期不得伪造新增数据。看板从${REFERENCE_DATE_009}起首页只展示上述六店，可切换查看六店详情，不计算门店平均值。

必须使用电子表格技能与artifact-tool生成和验证工作簿、截图。最终检查六个Sheet齐全且顺序正确、公式无明显错误、六张截图存在且非空、无商品明细文件，并确认公网显示当天最新日期、当前六店及五个新增指标。成功后报告工作簿、Sheet、截图目录数量、看板地址和最新日期；失败时明确卡点并保留已生成文件。
