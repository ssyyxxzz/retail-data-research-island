# 美团三分钟回复率与商品负反馈日报

- 原配置状态：启用
- 调度时间：06:00（Asia/Shanghai），准确规则以配置为准。
- 模板默认状态：暂停，不注册、不执行任务。
- 配置：[automation.example.toml](automation.example.toml)

## 流程正文（脱敏）

每天早上执行美团商家“今日体验分排名”双文件导出与日报处理，完整完成后在本任务汇报结果。

一、浏览器、入口和门店范围
1. 用户已取消专用分栏限制：直接使用当前已登录的 Chrome 美团商家端页面，可接管匹配 shangoue.meituan.com 的现有标签页，不再要求属于“📊 美团日报导出”分栏。优先使用商家等级页；多个候选时依据当前页面标题、地址和门店范围确认目标。
2. 整个导出流程必须保持“全部门店/默认范围”，不得选择任何单店、部分门店或自定义范围。若页面带着单店范围：在当前美团页面点击顶部范围栏，进入“门店管理”切回“全部门店”，再回到商家等级页刷新并确认顶部显示“全部门店”；不要勾选任何门店。无法确认时停止并汇报。
3. 优先使用用户指定的美团商家端入口；若失效，回退到 ${SERVICE_URL_005} ，再在同一美团标签页进入 ${SERVICE_URL_006} 。
4. 先验证 Chrome 控制能读取真实标签页。遇到页面控制超时时，按可用工具支持的故障恢复流程处理；可使用 Windows UI Automation 检查当前美团窗口，但必须能够确认网址和门店范围，并遵守不抢占前台的限制。工具明确停止或安全检查拒绝时不得绕过。连接连续失败时报告实际观察到的错误，不凭猜测断言配置、端口或登录状态有问题。不要将用户手动下载改成日常执行方案，自动任务仍负责双文件下载。
5. 不要把 Chrome 置顶、最大化或抢占用户前台。若必须截图，只截 Chrome 窗口且保持后台；后台无法取得有效 Chrome 窗口图时跳过截图，改用 UI Automation 文本和控件状态确认，禁止截整桌面。

二、导出“今日体验分排名”两份文件
1. 定位“今日体验分排名”区域顶部第一组按钮：左侧“导出门店排名”、右侧“导出指标明细”；不要点击下方“门店等级排名”的同名按钮。页面较窄时滚动主内容，必要时横向右滑。
2. 先点第一组左侧“导出门店排名”。若出现“数据量较大/预计5分钟通过站内信下发”，点“关闭”，不要点“前往查看”；等待生成后重新点击下载。
3. 再点第一组右侧“导出指标明细”。若出现同类提示，同样点“关闭”，不要点“前往查看”；生成后重新点击。优先使用 Windows UI Automation 的原生点击，避免 s3plus.meituan.com 被当作网页打开而触发 ERR_BLOCKED_BY_CLIENT。
4. 只有 ${LOCAL_PATH_016} 中实际出现本次新下载的两份文件才算成功：门店排名文件与“指标详情下载-*.xlsx”。逐次确认文件大小稳定、不是 .crdownload/临时文件，并记录完整路径；任意文件未出现都不得宣称成功或使用旧文件冒充。后续只处理指标详情，门店排名原样保留。

三、快速流式处理 Excel
1. 全程逐行/流式读取，只读取指标详情的“3分钟IM人工回复率”“商品负反馈率”“缺货退款率”；跳过配送准时率、有效配送信息回传率。${LOCAL_PATH_043} 也逐行读取。
2. 三分钟回复率取最大日期，只保留该日；回复率=首条消息3分钟内回复总数/顾客咨询总数，>=80%合格。
3. 商品负反馈完整保存当日快照，以日期更早的最新 ${LOCAL_PATH_044} 的“商品负反馈快照”为基线。按 poi_id + 商品SPU_ID + 问题类型比较，只取问题订单数量正向差额；长ID比较前清除零宽字符和文本前导单引号。没有基线时标记首次运行，不把全部记录误判为新增。
4. 逐行匹配问题分类表的“问题类型/问题归属”；未匹配为“未分类”。服务问题新增明细整行红橙色，含服务问题的汇总门店整行黄色；汇总增加服务问题新增数与是否含服务问题。
5. 生成并验证至少9个 Sheet：三分钟回复率、商品负反馈新增汇总、商品负反馈新增明细、缺货退款新增汇总、缺货退款新增明细、质量问题三次预警、商品负反馈快照、上一日商品负反馈快照、运行说明。
6. 输出到 ${LOCAL_PATH_044}，日期取三分钟回复率最大日期；同日期重跑可更新当日文件，不覆盖其他日期历史。检查公式错误、关键行数与每个 Sheet 的预览可读性。

四、缺货退款每日新增
1. 流式读取“缺货退款率”最大业务日期。若是订单商品明细结构，以 poi_id + 订单编号去重统计当日新增订单数并保留缺货退款件数；该数据本身视为当日新增，不与上一日二次差分。
2. 汇总按 poi_id + poi_name + city_name；明细尽量保留订单、商品、原因。同一源记录只统计一次，汇总订单合计必须与明细订单计数一致；无新增保留表头并注明暂无。日期与报告日期不一致时特别标明。

五、商品质量累计三次预警
1. 流式读取报告目录中日期早于或等于本次日期的历史“商品负反馈新增明细”，只统计问题归属=商品质量且新增问题订单数>0；同一日期、poi_id、商品SPU_ID、问题类型只计一次，本次只加当日新增。
2. 按商品SPU_ID跨日期、跨门店累计，达到3次及以上预警；列出累计次数、涉及天数、首次/最近日期、涉及门店、问题类型、当日新增次数、是否当日首次达到3次。

六、飞书自动发送
1. 仅在当日报表已生成、校验通过并保存到 ${LOCAL_PATH_045} 后执行；严禁发送其他日期的旧文件。
2. 使用“消息机器人”飞书 CLI，并以当前已授权的角色01用户身份发送给角色02；唯一接收人 open_id 为 ${MESSAGE_ID_008}。
3. 使用用户身份先上传当日报表文件，取得 file_key；再调用 POST /open-apis/im/v1/messages，receive_id_type=open_id，msg_type=file，把 file_key 发送给上述 open_id。不要使用机器人身份，也不要使用当前不可用的 im +messages-send 快捷命令。
4. 只有接口返回 ok:true 且取得 message_id 才算发送成功。发送失败时保留报表、汇报具体错误，不得宣称已发送。
5. 成功汇报增加：飞书接收人、发送文件和 message_id。

七、成功汇报
汇报门店排名文件、指标详情输入文件、输出文件、报告最大日期、回复率不合格门店数、商品负反馈新增门店数与订单数、服务问题新增门店数与订单数、缺货退款新增门店数/订单总数/件数/明细条数、累计达到3次的商品清单及当日首次达到3次的商品，以及飞书发送结果。失败时说明准确阻塞点并保留已有文件。
