# 每日牵牛花缺货数据汇总

- 原配置状态：启用
- 调度时间：04:00（Asia/Shanghai），准确规则以配置为准。
- 模板默认状态：暂停，不注册、不执行任务。
- 配置：[automation.example.toml](automation.example.toml)

## 流程正文（脱敏）

每天04:00（Asia/Shanghai）执行牵牛花缺货数据全流程。下载由Windows定时任务调用牵牛花接口执行，不再逐页点击。后台隔离9223仅承载已登录会话和平台签名，不切换用户正在使用的浏览器。先检查本地接口记录和实际Excel；正在运行时等待同一个程序完成，不另起重复进程或重复提交导出。没有当日有效来源且程序未运行时，执行下列本地入口；失败明确报告，不改回页面操作。只接受运行日创建的任务及通过字段、日期、SKU和门店范围校验的文件，禁止用历史分析成品替代原始数据。 Windows任务QNH-Independent-API-stockout，入口 ${LOCAL_PATH_018} -Group stockout。原始文件及独立接口下载记录.json保存在系统临时目录qnh_api_stockout\YYYYMMDD；从记录读取文件路径。接口筛选正常采购、可用库存最小和最大均为0、全部门店；不得拿六店库存文件充当全门店缺货。用 ${LOCAL_PATH_019} 和 ${LOCAL_PATH_020} 调用 ${LOCAL_PATH_021} 的流式处理流程，表头行号为 2，生成最终工作簿到 ${LOCAL_PATH_022}，文件名包含执行日期时间。最终工作簿必须包含两个工作表：一是原有“缺货数据结果”汇总；二是“实际售卖售罄明细”，按门店编码、商品SKU排序，列出所有30天总销量>0的商品，字段为门店/仓编码、门店/仓名称、商品SKU、商品名称、30天总销量、在途库存、是否未补货（在途库存=0标记为是，否则为否）。验证明细行数等于汇总表“实际售卖售罄商品”合计，且没有销量<=0的明细。完成后删除原始下载和所有临时文件，只保留最终结果。必须持续等待到最终 Excel 生成并验证非空；若登录失效、导出任务失败或超时，要明确报告具体原因，不要重复发起多个导出任务。
